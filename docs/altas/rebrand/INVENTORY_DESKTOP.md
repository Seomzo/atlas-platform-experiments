# Atlas Desktop (Electron) — Hermes Branding Inventory & Binary Dependency Map

Scope: `apps/desktop/` (+ `apps/shared` transport strings the desktop renders).
Generated by static inspection — **no code was modified**. Line numbers refer to current working tree.

Overall state: the desktop is **already largely rebranded**. `package.json`, build config, app name, About panel, icons, and the `atlas://` protocol are all Atlas. Two runtime "safety-net" translation layers (`atlasText` in `electron/main.ts:413` and `src/i18n/catalog.ts:7`) rewrite any residual "Hermes" strings to "Atlas" before display. What remains is (a) a handful of strings the rewriters do **not** catch (lowercase `hermes` CLI commands, URLs, env-var names shown in UI), and (b) a deep dependency web on `hermes*` binary/module names in the backend-spawn path — the critical part for removing `hermes*` entry points.

## 5. CRITICAL — backend binary/module resolution & spawn map

The desktop **never hardcodes a single binary**; it walks a resolver ladder. If `hermes*` entry points are removed from the shipped package, these are the exact touch points:

### 5a. Main backend resolver — `resolveHermesBackend()` (`electron/main.ts:3375-3521`)

| Rung | file:line | What it resolves | Breaks if `hermes*` removed? |
|---|---|---|---|
| 1. Env override root | main.ts:3376-3386 | `HERMES_DESKTOP_HERMES_ROOT` → python `-m hermes_cli.main` | Module name, not binary — breaks only if `hermes_cli` Python package is renamed |
| 2. Dev source root | main.ts:3392-3398 | `createPythonBackend(SOURCE_REPO_ROOT)` → `['-m','hermes_cli.main', …]` (main.ts:3339) | Same — module name |
| 3. Managed install | main.ts:3406-3408 → `createActiveBackend` (3355-3373) | venv python at `~/.atlas/hermes-agent/venv` + `-m hermes_cli.main` (3363) | Module name; dir name `hermes-agent` (main.ts:340) is a path constant |
| 4. **`hermes` on PATH** | main.ts:3415-3474 | `HERMES_DESKTOP_HERMES` override, else **`findOnPath('hermes')`** (main.ts:3430); probed with `--version` (`verifyHermesCli`, backend-probes.ts:107) | **YES — this rung searches ONLY `hermes`, never `atlas`.** If the shipped package installs only an `atlas` shim, rung 4 silently never fires (falls to 5/6 — still boots via python module, but an `atlas`-only CLI install won't be discovered). Add `findOnPath('atlas')` first. |
| 4b. Windows venv unwrap | main.ts:1440-1506 (`unwrapWindowsVenvHermesCommand`) | Regex `/^hermes(?:\.exe)?$/i` on basename (main.ts:1447) → re-spawns venv python `-m hermes_cli.main` (1493) | **YES — only recognizes `hermes.exe` shims, not `atlas.exe`.** An atlas-named venv shim will be spawned directly instead of unwrapped (loses env/PYTHONPATH hardening). |
| 5. System python + module | main.ts:3479-3503 | `canImportHermesCli(python)` → `-m hermes_cli.main` (3495); probe imports `hermes_cli.config` (backend-probes.ts:47) | Module name only |
| 6. bootstrap-needed sentinel | main.ts:3515-3521 | Triggers installer flow | n/a |

### 5c. Updater path

- `resolveUpdaterBinary()` main.ts:2274-2279 — spawns staged **`atlas-setup`/`atlas-setup.exe`** from HERMES_HOME (already atlas-named). Spawns at main.ts:2592 & 2674 with env `HERMES_PUBLIC_BRAND: 'atlas'`, `HERMES_BIN: 'atlas'`.

- `venvHermesShimPath()` main.ts:2311-2320 — update lock probe: prefers `venv/bin|Scripts/atlas(.exe)`, falls back to `hermes(.exe)`. Same migration note.

- `electron/bootstrap-runner.ts:119` — downloads install script from **`raw.githubusercontent.com/NousResearch/hermes-agent/<commit>/scripts/…`** — will point at upstream repo, not the DealerBox fork. **Must be repointed for the Atlas product.**

### 5f. Path/dir constants (internal, keep unless backend also moves)

- `resolveHermesHome()` main.ts:290-318 — honors `HERMES_HOME` env, else **`~/.atlas`** / `%LOCALAPPDATA%\atlas` (already atlas). But comments + test harness (`scripts/test-desktop.mjs:53-63`) still assume `~/.hermes` — the Python backend's default must match `~/.atlas` or config splits.
- `ACTIVE_HERMES_ROOT = <HERMES_HOME>/hermes-agent` main.ts:340 — checkout dir name; shared with install scripts.
- WSL font conf `99-hermes-wsl-windows-fonts.conf` main.ts:1130; temp scripts `hermes-desktop-update-*.sh` main.ts:2944/3050, `hermes-uninstall-*.sh` main.ts:8362; `.hermes-update-in-progress` marker (update-marker.ts) — all invisible plumbing, coordinate with installer if renamed.
- Windows git fallbacks `%LOCALAPPDATA%\hermes\git\...` main.ts:1804-1805, 1921-1922 — stale vs the new `%LOCALAPPDATA%\atlas` home; a fresh Atlas install on Windows will never have git at these paths. Update to `atlas`.

**Bottom line for removing `hermes*` entry points:** the desktop boots fine without any `hermes` **binary** (rungs 1-3, 5 use `python -m hermes_cli.main`), but you must (a) teach rung 4 + the Windows venv-unwrap regex about `atlas`, (b) keep or repoint the `hermes_cli` **Python module name** everywhere (`-m hermes_cli.main` ×6 sites, `hermes_cli.uninstall`, import probes, `hermes_cli/subcommands/dashboard.py` read, `hermes_cli/__init__.py` version read), and (c) repoint the two NousResearch GitHub URLs in bootstrap-runner/update-remote or updates will reinstall upstream Hermes.
